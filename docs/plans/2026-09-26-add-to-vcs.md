# Add to VCS from native file menus

## Goal

Support the next screenshot action, Add, through the existing localized **Add to
VCS** command in Explorer, editor-tab, and editor context menus. Deliver one
commit, version 0.35.10, and one ready PR from main after PR #288.

## Approach

- Reuse intelligit.fileAddToVcs and trackUnversionedFilesFromPanel. Existing panel
  payloads, repository checks, and multi-selection retain their behavior.
- Native URI input targets the clicked file's owning repository using the shared
  file-context resolver. An absent argument may use the active editor; malformed
  explicit input never borrows the editor.
- Accept one existing local file or symlink node. Refuse directories, non-file
  URIs, and untracked paths that fail the existing status recheck. No recursive
  directory adds or force-adding ignored files.
- Preserve the existing helper's acceptance of `?` and `A` statuses, including
  idempotent re-adds of already staged new files. The planning Git probe verified
  that intent-to-add does not overwrite their index blobs; test this invariant.
- Preserve intent-to-add semantics: move the selected untracked file into Changes
  without staging its content. Unsaved buffers need not be saved because this
  operation does not commit or stage file content.
- Refresh existing commit panels after success. Report Git failure separately
  from successful tracking followed by refresh failure; show concise localized
  feedback. Retain existing menu labels/translations; import new diagnostics via
  the localization CSV.
- Add the existing command to both shared file submenus with resourceScheme ==
  file. Runtime validation handles tracked/ignored files and folders.
- Add the command to the standard no-repository placeholder registration. Use
  its existing actionable open/initialize-repository message in that mode.

## Checks

Contract-derived RED/GREEN for URI ownership/fallback, invalid targets, legacy
panel payloads, intent-to-add, and unrelated index/worktree preservation. Real
VS Code Explorer invocation proves the menu and actual resulting Git status.
Run required repository checks, production packaging, independent review, and
staged graph analysis before committing.

## Out of scope

No new Git engine behavior, recursive folder tracking, native multi-selection,
commit, push, publish, or unrelated menu action. Existing panel selection support
is unchanged. Reuse the available managed checkout on codex/menu-add-to-vcs,
based on main 46e1c5a8c73be598cd7b8aa0dea02b767b20cee3.
