# Plan: Marketplace review/rating prompt

_Locked via grill — by Claude + Mahesh. v10: the v9 design with the cross-window locking machinery cut, on Mahesh's call after Codex Rounds 1–8 (46 findings; rounds 4–8 produced 11 CRITICALs, all inside that machinery)._

## Goal

Grow marketplace ratings for IntelliGit (VS Code Marketplace + Open VSX) by asking proven, happy users — at a success moment, at most 3 times, never after they rate or decline — to click once and land on the exact review page of the marketplace matching their product. Direct in-dialog star submission to either marketplace is **impossible** (no write APIs; publisher-token posting = fake reviews), so the feature is: perfect timing + one-click routing + a never-ask-again guarantee that survives crashes, restarts and multiple windows. Zero backend, zero telemetry. Both listings verified live 2026-08-01: Open VSX `MaheshKok/intelligit` v0.22.0 (reviewCount 3, averageRating 5.0, `/reviews` route valid) and VS Marketplace `MaheshKok.intelligit`.

## Approach

1. **Success signal: one module-level hook in `src/git/executor.ts`** — static/module-scoped optional callback `GitExecutor.onCommandSuccess?: (gitSubcommand: string, argv: readonly string[]) => void` (plain function, no `vscode` import), consulted by every executor instance (`deriveFor()`-derived and undocked included — structural). **Both fire sites go through one exported exception-swallowing dispatcher** `notifyGitSuccessSafely(cmd, argv)`: (a) the executor after any mutating command resolves exit 0; (b) `src/services/publishService.ts` after `runGitPushWithAskpass()` (the `execFile` bypass) succeeds — a listener throw can never convert a succeeded push into a reported failure. Set during activation; resettable for tests.
2. **New file `src/services/reviewPrompt.ts`** — `ReviewPromptService`, constructed during activation (`src/activation/repositoryMode.ts` area) with `ExtensionContext`. **Init is containment-wrapped**: `mkdir globalStorageUri/reviewPrompt/` recursive, `setKeysForSync(['…status','…askCount','…snoozedUntil','…lastAskAt'])`, **mirror→latch reconciliation** (a synced terminal status with no local latch seeds the latch — recovers a decision made on another machine, or one whose local latch write failed before a restart), hook registration. Any failure logs, leaves the hook unset (feature silently disabled), activation continues.
3. **Counting semantics**: only `commit` and `push`. Push exclusions (+0, pinned by tests incl. the three repo `push --delete` call-site shapes in `src/commands/branchCommands.ts` / `src/services/gitHelpers.ts`): `--delete`, `-d`, `:`-prefixed refspec, `--dry-run`, exact `-n`. Commit +1, push +1, commit-and-push +2, sync's push leg +1, publish push (either path) +1, deletions/dry-runs +0, failures/cancels +0, merge/rebase/checkout/stash +0.
4. **State — one durable latch plus plain Memento**:
   - **Terminal latch** — `globalStorageUri/reviewPrompt/terminal.json`, `{ status: 'rated'|'declined', decidedAt }`, written **write-once with flag `'wx'`** and **never deleted, overwritten or repaired**. **Existence is authoritative; content is advisory** — `'wx'` makes *creation* exclusive but does not publish content atomically, so a writer that dies between create and write leaves an empty file; every reader treats an existing latch as terminal whether or not it parses (the user decided; only the detail is lost). On `EEXIST` the loser **reads the winner's content and mirrors that**, never its own status, so a rated-vs-declined race cannot leave latch and mirror disagreeing. This is the whole never-ask-again guarantee: one atomic filesystem primitive, no lock.
   - **Counters and ask ledger** — `globalState` (`intelligit.reviewPrompt.*`): `successOps`, `activeDays`, `lastActiveDay`, `installedAt` (machine-local, never synced) and `askCount`, `snoozedUntil`, `lastAskAt`, `status` (synced via `setKeysForSync`, so a second machine inherits the decision). `status` is **terminal-only** (`rated`/`declined`; absence = pending) and every write to it is a **merge-write** (read → keep any existing terminal → write), so no counter update can clobber a terminal.
   - Normalizing loader with hard defaults for every field; empty state is a first-class test case.
5. **Ordering** — every `handleGitSuccess` appends to a module-internal promise queue (`queue = queue.then(work).catch(log)`) so a single window never interleaves with itself. Inside the queued section: (a) increment and persist the usage counters; (b) **gate** (all cheap, all local): setting enabled · `successOps ≥ 30` post-increment · `installedAt ≥ 14d` · `activeDays ≥ 5` (`29→30` and `4→5` boundaries can themselves trigger, both tested) · session flag unset · `askCount < 3` · `now > snoozedUntil` · **latch absent and no in-process intent**; (c) **reserve the ask** — `askCount+1`, `snoozedUntil = now+30d`, `lastAskAt = now`, persisted **before** anything is shown, so a restart with the toast still open costs one reserved ask and never a 4th display; (d) **re-check the latch** (another window may have recorded a decision since (b)); (e) **show the notification, detached**. The per-window session flag is set synchronously before the first `await` of the show path.
6. **Response handling** (detached, single chain, terminal `.catch(log)`) — a decision needs no lock and no coordination: `[Rate IntelliGit]` → (i) set the **in-process terminal intent** synchronously, which silences this window immediately; (ii) write the latch `'wx'` — success *or* `EEXIST` both mean durable; (iii) merge-write `status` to `globalState` best-effort (`EEXIST` → mirror the winner's status; unparseable → mirror nothing, log); (iv) `openExternal(getReviewUrl())`. `[Don't ask again]` → identical with `status='declined'` and no `openExternal`. `[Later]` / dismissal → nothing further; the reservation already is the snooze.
   **If the latch write fails** (EIO, disk full, read-only home): write the terminal to `globalState` **before** `openExternal` — it is restart-readable and is exactly what init reconciliation seeds the latch from — and keep the in-process intent so this window shows nothing further. **There is no in-process retry ladder** (see PLAN-REVIEW-LOG.md §Deliberately not done): the intent already silences this window for its lifetime and init reconciliation seeds the latch from the mirror on the next start, so a retry would only matter when latch *and* mirror both fail, which is the residual booked under Risks. Mirroring is best-effort in the other direction too — a rejected `globalState` write is logged and never prevents `openExternal`, because a user who clicked Rate and is silenced without reaching the review page is the worst outcome available.
   **Toast copy locked** (EN, asserted in unit + acceptance): `Enjoying IntelliGit? A quick rating helps others find it.` — buttons `Rate IntelliGit` / `Later` / `Don't ask again`.
7. **Routing `getReviewUrl()`**: exact-match allowlist `{'Visual Studio Code', 'Visual Studio Code - Insiders'}` on `vscode.env.appName` → `https://marketplace.visualstudio.com/items?itemName=MaheshKok.intelligit&ssr=false#review-details`; anything else (Cursor, Windsurf, VSCodium, unknown forks — no `startsWith`) → `https://open-vsx.org/extension/MaheshKok/intelligit/reviews`. Named constants.
8. **Drive-by fix in `src/git/repositoryLock.ts`** (found while evaluating the lock, kept even though the review prompt no longer uses it): `isProcessLive()` returns `true` only for `EPERM` and treats *every* other `process.kill(pid, 0)` error as dead, so an unexpected errno silently authorizes takeover of a live owner. Report dead only on `ESRCH`, live on anything unrecognized (fail closed), with a unit test per branch. This hardens the existing repository-mutation lock (`src/activation/repositoryMode.ts:120`) in the safe direction.
9. **Setting + l10n via the repo pipeline**: `intelligit.reviewPrompt.enabled` (boolean, default `true`) with the `%configuration.*.markdownDescription%` pattern + base `package.nls.json` + 11 locale nls files; runtime strings via `vscode.l10n.t()` + `l10n/` bundles. Workflow: `bun run l10n:sync` → populate 11 locale columns in the CSV → `bun run l10n:translate -- --only-missing` → `bun run l10n:import` → `bun run l10n:validate` + `bun run l10n:audit`.
10. **Tests** (vitest, `tests/unit/`, TDD-first; per-file hoisted `vi.mock("vscode", …)` — reference `tests/unit/core/notifications.test.ts`; hook, session flag and clock injectable; fs via temp dirs):
    - Gating: every threshold; boundaries `29→30` and `4→5`; snooze; cap at 3; disabled setting; empty state; active-day counted once per day; latch present → never asks; in-process intent → never asks.
    - Ordering: reservation persists **before** `showInformationMessage`; post-reservation latch re-check → no toast; dismissal inert; detached-chain rejection contained; queue serializes concurrent successes within a window.
    - Terminal latch: `'wx'` write-once, second writer gets `EEXIST` and mirrors the **winner's** status (rated-vs-declined contenders agree); **empty/corrupt latch still gates as terminal** and is never repaired; latch never deleted.
    - Durability: latch write rejects → `globalState` terminal written before `openExternal` → **a freshly constructed service seeds the latch from it at init and never asks again**; latch + mirror both reject → in-process intent still silences the window for its lifetime; `openExternal` fires on every failing-write path, including a rejected mirror write; all failures logged.
    - Mirror: `status` is only ever written with a terminal value, via merge-write; a counter update cannot clobber it; a mirror rejection after a reserve still shows the toast.
    - Routing: stable + Insiders → MS; Cursor and a fork whose name starts with "Visual Studio Code" → Open VSX.
    - Counting contract: commit +1 · push +1 · commit-and-push +2 · failed/canceled +0 · merge/checkout/stash +0 · `--delete`/`-d`/`:refspec`/`--dry-run`/`-n` +0 (three repo delete-site shapes pinned) · askpass first-publish +1 · derived/undocked executors consult the hook.
    - Dispatcher: listener throw swallowed at both sites; askpass-throw-preserves-publish-success.
    - Init containment: storage failure → feature disabled, activation completes.
    - `isProcessLive`: `ESRCH` → dead, `EPERM` → live, unknown errno → live.
    - Copy: EN message + 3 buttons verbatim.
11. **Acceptance run (dev host)** — four independently reseeded scenarios (temporary local seed patch, never staged), each from a fresh one-below-threshold seed, with restarts and time advancement (`snoozedUntil` seeded past to re-arm): S1 Rate (localized toast; MS URL opens; latch survives restart; no re-ask) · S2 Later (reservation persists; snooze-past re-arms; cap holds at 3) · S3 Dismiss (same semantics as Later) · S4 Don't-ask (latch survives restart; never re-asks). Then **revert the seed patch and verify `git status --porcelain` clean for tracked files BEFORE any validation gate**.
12. **Validation gates** (AGENTS.md): `format:check`, `lint`, `lint:strict` (TSDoc on new public API), `typecheck`, `architecture:check`, **`test:coverage`** (floors 88.5/83/80.5/88.5 — thresholds only activate there), `l10n:validate`, **`l10n:audit` as a delta** vs recorded baseline (currently 9 advisory findings; gate = no new reviewPrompt findings, no count increase), `build`.

## Key decisions & tradeoffs

- **Cut the cross-window lock (v10, Mahesh's call)** — v6–v9 protected the ask ledger with `RepositoryLock`, `isOwner()` fencing at three rename sites, a lock-protected ledger file and mirror reconciliation. Rounds 4–8 produced 11 CRITICALs, every one of them inside that machinery, with no convergence. It bought exactly one thing: two windows cannot each consume an ask in the same second. It did **not** buy the never-ask-again guarantee — the write-once latch does that on its own. Removing it deletes the entire defect class at the price of a rare duplicate toast (see Risks). Roughly half the code.
- **The latch is the guarantee; Memento is convenience** — `'wx'` create is atomic and single-winner on every filesystem this extension runs on, needs no lock, and survives crashes; `globalState` carries the counters, the cap and the Settings-Sync copy, where the worst failure is an extra ask, never an unwanted one after a decision.
- **Existence authoritative, content advisory** — the one rule that makes a half-written latch safe, and the reason no reader ever repairs or deletes it.
- **Reserve before show** — an ask is spent when it is displayed, not when it is answered, so a crash mid-toast cannot buy a fourth prompt.
- **One dispatcher-guarded module hook + one askpass fire** — all executor traffic structurally covered; the single `execFile` bypass covered explicitly; argv-level semantics exclude deletions and dry-runs.
- **Native notification, no webview star dialog** — stars cannot transfer to either marketplace; fewest clicks to a real review wins. Star-funnel deferred.
- **Conservative trigger (30 ops / 14 days / 5 active days), 3 asks, 30-day snooze, dismissal counts, visible setting, unknown forks → Open VSX** — user-locked at the grill.

## Risks / open questions

- **Duplicate toast in a two-window race** (the price of cutting the lock): two windows that both cross the threshold within the same moment can each reserve and show, because `globalState` is a host-local cache with no cross-host write ordering. Bounded by the 30-day snooze and the per-window session flag; the user sees one extra notification, and either window's Rate/Decline creates the latch that silences both. Accepted deliberately over five rounds' worth of locking defects.
- **The 3-ask cap can soften** the same way, to at most one extra ask per snooze cycle for users who keep several windows open simultaneously. Accepted.
- **Sub-second toast-vs-latch window**: the pre-show latch check and `showInformationMessage` cannot be atomic across processes, so a decision landing in the microseconds between them still yields one toast. Non-repeating — the latch is permanent.
- Loss of the latch *and* the synced status → one fresh-install-equivalent re-ask cycle once the window that held the intent closes. There is no retry ladder to catch this (see line 20), so this is the residual both write paths fail into. Accepted.
- MS marketplace review page requires a Microsoft sign-in; some clicks will not convert. Unavoidable.
- Exotic filesystems (network homes): `'wx'` atomicity is weakest there; every latch error path fails toward not-asking and logs.

## Out of scope

- Webview star-capture funnel / GitHub-issue routing for unhappy users (documented v2 candidate).
- Telemetry, analytics, any backend, any network call besides `openExternal`.
- Prompts for sponsor/donate/changelog.
- Attempting to post or scrape reviews on either registry.
