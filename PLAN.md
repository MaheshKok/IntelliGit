# Plan: PyCharm-Parity Shelve for IntelliGit

_Locked via grill — by Claude + maheshkokare. Revised after Codex rounds 1–4._

## Goal

Add full JetBrains/PyCharm **Shelve** functionality to the IntelliGit VS Code extension: a patch-based mechanism, completely independent of `git stash`, that saves selected working-tree changes as named shelves stored outside the repository, reverts them from the working tree, and later unshelves them — wholly or partially — with 3-way conflict resolution for text files and explicit choice actions for structural conflicts. The Shelf UI mirrors the existing PyCharm-style Stash tab in the commit panel, and the feature set covers all three agreed tiers plus the documented PyCharm behaviors verified against a live IDE: Shelve/Save-to-Shelf/Unshelve (silent and dialog forms), rename/delete/diff, base-revision recording with repository-history fallback, patch import/export, "already unshelved" ghosts retained until explicit deletion, drag-and-drop with Ctrl-to-keep, settings, command palette, i18n across 11 locales, a11y. Shelving must be lossless (including staged-only content), crash-recoverable at every destructive step, serialized across VS Code windows, correct in linked git worktrees, and safe against hostile or tampered patch input. Where IntelliGit deliberately extends PyCharm (e.g., shelving untracked files), the divergence is explicit and documented.

## Approach

Phases are commit milestones on branch `codex/pycharm-shelve-parity` (stacked on `codex/pycharm-stash-parity`, which lands first). Every phase follows repo TDD policy (spec-derived failing tests first, 80%+ coverage).

### Phase 0 — Ground truth + cross-cutting infrastructure

1. **Live PyCharm parity matrix (ground truth before design freezes).** Run a current PyCharm against a scratch repo and record: exact Shelve/Save to Shelf/Unshelve dialog fields and defaults, unversioned-file handling (per current official docs unversioned files cannot be shelved — IntelliGit supports them as a **labeled extension**), base-revision fallback when "shelve base revisions" is off (repository history), drag-and-drop semantics including **Ctrl-drag = copy/keep**, ghost retention (retained until explicitly deleted — no age-based auto-delete by default), Clean Up dialog contents. Committed as `docs/shelve/pycharm-parity-matrix.md`; every deliberate divergence listed there.
2. **Git-directory resolution for linked worktrees.** All shelf infrastructure paths resolve through Git, never literal `.git/` (in a linked worktree `.git` is a *file*, and literal paths fail `ENOTDIR`): `gitDir = git rev-parse --git-dir`, `commonDir = git rev-parse --git-common-dir`. The **repository transaction lock lives in the common dir** (`<commonDir>/intelligit/repo.lock`) — serializing IntelliGit mutations across all worktrees and windows of the repository; **recovery staging lives in the worktree's own git dir** (`<gitDir>/intelligit/recovery/<txId>/`). The EXDEV abort (step 7) remains the backstop for exotic placements.
3. **Per-repository mutation serialization — in-process queue + cross-process lock.**
   - In-process: activation-owned async queue keyed by repo root serializing every mutating entry point. Task one is the **inventory**: commit/stage/rollback/stash in both `CommitPanelViewProvider` and `UndockedViewProvider`, plus checkout, reset, cherry-pick, rebase, revert, pull in `commitBasicActions.ts`, `commitHistoryActions.ts`, `branchCommands.ts`, and command-palette registrations.
   - Cross-process: every IntelliGit mutation additionally acquires the common-dir repo lock (owner nonce + heartbeat + liveness — step 5). External non-IntelliGit git processes cannot be locked out — that residual is handled by per-step revalidation + fingerprint-guarded rollback (step 8) and is named as bounded.
   - **Transactions are short**: queue/lock never held across interactive UI; conflict sessions re-acquire with preconditions (step 24).
   - Unit tests: per-repo serialization, cross-repo parallelism, cross-process and cross-worktree contention, precondition aborts.
4. **Byte-safe, exit-code-aware Git runner.** `runBinary` (Buffer stdout, streamed to disk) + per-call expected-exit-codes (`diff --no-index` exits 1; `apply --check` exits 1). Patch bytes never round-trip through JS strings.

### Phase 1 — Shelf storage + patch primitives (no UI)

5. New module `src/shelf/`:
   - **`model.ts`** — `ShelfFileEntry` with **explicit per-layer blocks**: stable `changeId`, `indexBlock` and `worktreeBlock` references (each with own path, `renamedFrom`, status M/A/D/R/T, mode before/after, content hashes), `binary`, `untracked`, `baseAvailability: "full" | "history" | "none"`, `exactReconstruction: boolean`, lifecycle state (`shelved | applied | retained`). One path/status pair cannot model staged `a→b` + worktree `b→c`; per-layer blocks can, and partial selection always operates on whole entries. Symlinks, submodules, unmerged-stage paths, intent-to-add, `skip-worktree`/`assume-unchanged` paths are **rejected at shelve time** with explicit per-file errors. Every Git state is supported or explicitly rejected.
   - **`store.ts`** — shelf CRUD on disk. Layout: `<shelfRoot>/catalog.json` (shelf list + `catalogGeneration` + **durable idempotency ledger**: token, operation, payload hash, result — replayed on retry before any CAS, token reuse with a different payload rejected), per shelf a **content-addressed `objects/` directory** (patches, base blobs, raw before/after blobs — stored once, immutable) and small immutable `gen-<N>/manifest.json` files that *reference* objects, with a single atomically-replaced `current` pointer — generations never duplicate large artifacts; unreferenced objects are garbage-collected under the store lock. Per-artifact SHA-256 checksums; `schemaVersion`; parent-dir fsync. **Locking**: owner nonce + heartbeat; takeover requires stale heartbeat AND failed liveness probe — never age alone (no PID-reuse split-brain); otherwise "shelf busy" is surfaced. `journal.json` records every multi-step transition (`shelvePendingRevert`, unshelve pending→applied, ghost transitions) with per-path progress for resume/rollback. Corrupt entries skipped for listing but surfaced, never silently.
   - **`paths.ts`** — default `<globalStorage>/shelves/<repoId>/` (repoId = 16 hex of SHA-256 of normalized repo-root realpath); `intelligit.shelf.path` override **machine-scoped**, repoId always appended; dirs `0700`, files `0600`; symlinked roots rejected.
   - **`patchIO.ts`** — indexed block model per logical change (rename pairs atomic; per-layer blocks per entry), byte offsets for partial apply; git binary patches, `-M` rename headers, mode changes, plain unified diffs (import).
6. **Faithful patch generation + per-layer materialize test.** Fixed applyable flags: `--binary --full-index -M --no-textconv --no-ext-diff --no-color`. Materialization is **layer-correct**: `index.patch` verified base→captured-index-blobs; `worktree.patch` verified sequentially index→actual-worktree-bytes, including modes and absent sides. Files whose reconstruction differs (clean/smudge, EOL) store **raw before+after blobs** and are flagged `exactReconstruction: false`.
7. **Recovery staging is same-filesystem by construction.** Recovery objects stage under `<gitDir>/intelligit/recovery/<txId>/` (worktree git dir — same volume as the working tree in the standard case), then **copy + fsync** into shelf storage; unavailable same-FS staging (`EXDEV`) **aborts safely before touching anything**. Never a cross-device rename on the destructive path.
8. **Journaled, recoverable revert (the destructive step).** Runs under queue + repo lock as a `shelvePendingRevert` journal transaction. Per path: current filesystem object atomically renamed into recovery staging (the move IS the preservation); base state then created **fail-closed**: `O_EXCL` + `O_NOFOLLOW` where the platform supports them, `lstat` containment checks immediately before and after each write, and refusal on filesystems where these guarantees don't hold (Node exposes no `openat`-family confinement — this **named residual** is documented and bounded by recovery retention, not hand-waved by fictional APIs). Path reappearance mid-transaction (editor recreate) → **abort and roll back**. Recovery-object hashes verified before journal commit; index changes via Git's own `index.lock`; per-step HEAD/index revalidation detects external git activity. **Fingerprint-guarded rollback**: rollback restores only paths/index entries whose current state still matches what the transaction itself wrote — if a third-party git command (checkout/reset) changed them mid-transaction, both states are retained and explicit recovery UI is offered; automatic rollback never overwrites a third party's result. Revert always targets the pinned base OID; unborn base reverts against Git's empty tree. **Recovery retention has a defined bound**: originals (the moved inodes) are retained for a minimum window (default 24h) during which nothing may evict them; when capacity is exhausted, **new destructive operations are refused** ("recovery full") rather than evicting inside the window; recovery purge is a **separate explicit command**, decoupled from shelf deletion (deleting a shelf does not silently delete its recovery snapshots).
9. Unit tests: dual-layer round-trips (staged-only, unstaged-only, mixed, divergence, staged-rename + worktree-rename chains, add/delete cancellation, delete/recreate), untracked, binary, empty file, CRLF + filter/EOL (raw-blob path), unborn repo, **linked-worktree layout (`.git` file)**; journal resume/rollback at every crash point incl. path-reappearance abort and third-party-interference retention; EXDEV abort; generation-pointer atomicity; object GC refcounts; idempotency-ledger replay; lock nonce/heartbeat incl. PID reuse; corrupt-manifest tolerance; repoId stability; override scoping.

### Phase 2 — Host-side service, protocol, validation

10. `src/services/shelfService.ts` — orchestrates GitOps + store per repo root: `shelve({name, paths, silent, keepLocal})` (**`keepLocal: true` = PyCharm "Save to Shelf"** — record without reverting), `unshelve({id, changeIds?, removeFromShelf, mode})`, `deleteShelf`, `renameShelf`, `exportPatch`, `importPatch(fileUris)`, `restoreGhost`, `cleanUp(selection)`, `resolveStructural(...)`, `purgeRecovery()`, `listShelves`, `getShelfFiles(id)`, `getShelfFileContents(id, changeId)`, `resumePendingRecovery()`. All mutations inside queue + repo lock.
11. **Two precisely defined unshelve modes (`--3way` banned — implies `--index`, stages results).**
    - **Flattened (default, PyCharm semantics):** applies each entry's net base→final content change to the working tree only, unstaged. Where layers cancel (net empty, `index.patch` nonempty — the B/A case), index-layer content is applied unstaged and flagged `flattenedResidue`. The user's index is untouched — asserted byte-identical to its pre-unshelve fingerprint.
    - **Exact-state (`mode: "exactState"`, off by default):** restores both layers. Same-path index divergence → entry **refused** with a typed per-entry result (user unstages first) — never silently merged. Post-condition asserts the index equals the expected restored index.
    - Per entry: (a) **`exactReconstruction: false` entries skip `git apply` entirely** — raw-before compared to current file; equal → raw-after written (clean), different → structural-choice actions; `exactReconstruction: true` entries use patches; (b) clean text blocks via `git apply --check` → applied working-tree-only; (c) conflicting **regular-text M/M blocks with an available base** → `git merge-file` (current, base, patched-base) in temp files; base resolution: stored blob → **repository-history via pinned `baseCommit`** (PyCharm fallback) → none; (d) **structural conflicts** (binary, invalid-UTF-8, delete/modify, rename, mode) → explicit per-file choice actions (Keep Local / Use Shelved / delete- and rename-variants); (e) `baseAvailability: "none"` blocks are clean-apply-only; failures retain the block and offer raw patch inspection.
12. Protocol (`src/webviews/protocol/commitPanelMessages.ts`): snapshot gains `shelves: ShelfEntry[]` (each with `generation`), `catalogGeneration`, `shelfFiles: ShelfFileEntry[]`, `selectedShelfId`. Outbound: `shelveSave`, `shelfSelect`, `unshelve`, `shelfDelete`, `shelfRename`, `shelfDiff`, `shelfCompareWithLocal`, `shelfExportPatch`, `shelfImportPatch`, `shelfRestoreGhost`, `shelfCleanUp`, **`shelfResolveStructural`** (generation- and per-path-fingerprint-guarded resolution of pending structural conflicts), `shelfPurgeRecovery`. **Operation-specific request unions**: single-shelf mutations carry `shelfId` + expected `generation`; create/import carry an **idempotency token** + expected `catalogGeneration` (durably ledgered — lost-response retries replay the recorded result); multi-shelf cleanup carries `catalogGeneration`. CAS under the store lock; staleness returns typed `staleShelf`/`staleCatalog`. `shelfMutationCompleted` carries `{requestId, status: "ok" | "partial" | "conflicts" | "staleShelf" | "staleCatalog" | "busy" | "recoveryFull" | "error", entries: PerEntryResult[]}` where `PerEntryResult` is a **discriminated per-entry union**: `applied | conflicted | retained | flattenedResidue | refused | structuralPending`, plus `shelfId?`, `newGeneration?`, `newCatalogGeneration?` — created/imported shelves return their ID; partial success, refusals, and conflicts are first-class.
13. `src/views/messageValidation.ts`: shelf messages validated as untrusted webview input — ids/changeIds/generations/tokens type- and existence-checked; **invalid or overlong names rejected explicitly, never silently rewritten**; names are metadata only; `shelfId` host-generated.
14. **Hostile-input validation at the patch/store boundary.** Imported patches and re-read manifests are untrusted: strip-level normalization; **platform-aware segment validation** — case-insensitive `.git` rejection (`.GIT`, mixed case), Windows drive/UNC prefixes, NTFS alternate data streams, reserved device names, no `..`/absolute escapes; canonical containment; apply-time write discipline per step 8 (`O_NOFOLLOW`/`lstat` bracketing, fail-closed); type allowlist; **expansion bounds**: per-file and aggregate decoded-output limits, hunk/line-count limits, declared-result-size validation before allocation, bounded streaming decode. Fixtures: real PyCharm patches + malicious (traversal, `.git/hooks/`, `.GIT` casing, ADS, device names, symlink swaps, binary bombs).
15. Host wiring in **both providers** (`CommitPanelViewProvider`, `UndockedViewProvider`), `commitPanelActions.ts`, `commitPanelRepositoryRuntime.ts` snapshot assembly, RefreshService, working-tree-changed events, startup `resumePendingRecovery()`.
16. Unit tests: validation matrices (webview + patch boundary + names + platform paths), unshelve-mode branches (flattened, residue, exact-state refusal, raw-blob path, clean/merge-file/structural, history-fallback), per-mode post-conditions, CAS staleness, idempotency replay + conflicting-payload rejection, per-entry result unions, queue+lock serialization, conflict-session precondition re-acquire.

### Phase 3 — Shelf tab UI (core)

### Phase 4 — Advanced parity

22. Base revisions (setting `intelligit.shelf.recordBaseRevisions`, default **on**): stored in `objects/`; when off, conflict bases resolve from repository history via pinned `baseCommit` (documented PyCharm fallback); `git gc` risk applies only to the fallback path and surfaces as a `baseAvailability` downgrade, never a crash.
23. Import/Export: "Import Patches…" (`.patch`/`.diff`, git-format and plain unified) through the Phase-2 boundary into a new shelf. "Create Patch…" writes a **flattened** patch — **documented lossy for staging metadata**; round-trips content with PyCharm and git. No custom archive format.
24. **Shelf-conflict resolution UI.** Content-backed conflict session **strictly for regular-text M/M**: three text payloads (base, current, patched-base), output written to the working tree only — no staging, no abort semantics (the existing `MergeEditorPanel` git-stage contract is wrong for shelves; only its webview components are reused). Session runs **outside queue/lock**; apply/cancel re-acquires with preconditions **including per-path content/type/mode fingerprints**. **Stale apply/cancel never overwrites or silently restores**: both versions preserved (current parked in recovery), explicit user choice required. Structural conflicts resolve via `shelfResolveStructural` — never this editor.
25. Ghost lifecycle (**PyCharm default: retained until explicitly deleted**): fully-unshelved-and-removed shelves become ghosts (journaled); "Clean Up Shelf…" offers delete-all-ghosts or older-than-N-days; **no automatic deletion unless opted in** (`intelligit.shelf.cleanupAfterDays` default **0 = never**); ghost delete is permanent for the shelf, while recovery snapshots follow their own retention (step 8). Partial unshelve with remove marks applied entries; shelf stays live until empty.
26. Integration tests on real temp git repos: full round-trips (flattened index-identity; exact-state expected-index; B/A recovery both modes); Save-to-Shelf (tree untouched); text conflict → merge-file → conflict session incl. per-path staleness and both-versions preservation; structural conflicts incl. rename chains; exact-state refusal; unborn repo; **linked worktree**; import/export incl. PyCharm fixture; filter/EOL via raw blobs; journal resume/rollback at every crash point incl. third-party-interference (fingerprint-guarded rollback retains both states); two-window and cross-worktree lock + CAS contention; history-fallback base; recovery-window refusal when full; idempotent create/import retry.

## Key decisions & tradeoffs

1. **Patch files, not git refs** (grill-locked). True PyCharm mechanics; cost: we own fidelity and merge strategy.
2. **Dual-layer capture with per-layer blocks** (index.patch + worktree.patch; per-entry `indexBlock`/`worktreeBlock`). Single-patch capture is provably lossy (B/A); single path/status metadata provably inexpressive (rename chains). Partial operations act on whole entries.
3. **Two named unshelve modes** — flattened (default; index untouched; residue surfaced) and exact-state (expected-index assertion; same-path divergence refused). Per-mode, testable guarantees.
4. **Journaled move-to-recovery revert**: same-FS staging in the **worktree git dir resolved via `rev-parse`** (linked-worktree correct), O_EXCL+O_NOFOLLOW fail-closed writes with lstat bracketing, hash-verified recovery, defined **minimum retention window** with refuse-when-full (no silent eviction), purge decoupled from shelf deletion, and **fingerprint-guarded rollback** that never overwrites third-party git results (both states retained + explicit recovery). Two named residuals — open-descriptor external writes, and Node's lack of `openat`-family confinement — are documented and bounded by retention, not hidden.
5. **In-process queue + cross-process repo lock in the git common dir** (owner nonce + heartbeat + liveness; never stolen by age) covering the full mutating-entry-point inventory across windows *and* worktrees. Third-party git processes are detected and rolled back safely, not locked out (impossible).
6. **`git merge-file` + base fallback chain (stored blob → repo history → none); `--3way` banned.** Interactive merge is text-M/M-only; structural and inexact files use explicit choice actions; **`exactReconstruction: false` files bypass `git apply`** (raw before/after blobs).
7. **Faithful generation enforced per layer**: fixed flags + layer-correct materialize tests + raw blobs.
8. **Content-addressed shelf `objects/` + tiny generation manifests + atomic current pointer** — immutable generations without duplicating large artifacts; lock-protected GC; **durable idempotency ledger** so lost create/import responses replay instead of failing CAS; operation-specific CAS (shelf vs catalog generation).
9. **`.patch` export is flattened and documented lossy**; full fidelity stays internal. No custom archive format.
10. **globalStorage keyed by repo-root path hash, machine-scoped override** (grill-locked + hardened).
11. **No changelists** (grill-locked): selection → shelve; working tree ← unshelve. Future epic.
12. **PyCharm-verified defaults** (Phase-0 matrix): Save to Shelf exists; ghosts retained until explicit deletion (`cleanupAfterDays` default 0); Ctrl-drag keeps; base falls back to repository history. **Untracked-file shelving is a labeled IntelliGit extension.**
13. **New per-repo mutation queue + repo lock as Phase 0** — the previously assumed gate does not exist; building it first closes existing race windows too.
14. **Worktree/branch stacking** (grill-locked): merge order stash-parity → shelve.

## Risks / open questions

- **Transactional revert complexity** remains the main implementation risk (journal + recovery + fail-closed writes + fingerprint-guarded rollback). Mitigation: Phase 1 ships it standalone with crash-point tests before any UI; `resumePendingRecovery()` startup hook; manual recovery + purge commands; defined retention window.
- **Named unpreventable residuals**: (a) an external process holding an open descriptor/hardlink to a moved file can write after every check — bounded by minimum-window retention of the original inode; (b) Node lacks `openat`-family confinement — bounded by O_NOFOLLOW + lstat bracketing + fail-closed refusal on unsupported filesystems. Both documented in security notes.
- **Index-preservation guarantees** rest on merge-file strategy + per-mode post-conditions; reintroducing `--3way` breaks them — guarded by regression test.
- **Filter/EOL divergence** handled via layer-correct materialize tests + raw blobs; storage inflation bounded by content-addressing + GC.
- **Cross-process contention**: common-dir repo lock + nonce/heartbeat/liveness; PID-reuse tested; "shelf busy"/"recovery full" are surfaced states, not errors.
- **Plaintext patches may contain secrets** — same exposure class as PyCharm's shelf; 0700/0600 + README note; encryption out of scope.
- **Multi-root workspaces**: strictly per repository root; cross-repo shelve rejected.
- **Open questions**: none — previous PyCharm-default questions resolve via the Phase-0 live parity matrix (committed deliverable).

## Out of scope

- Changelists (and unshelve-into-changelist targeting).
- Reading/writing JetBrains' `.idea/shelf` XML store directly (interop via patch import/export).
- A custom full-fidelity shelf archive/export format (export is flattened `.patch`, documented lossy).
- Shelf sync across machines or remotes; encryption at rest.
- VS Code native SCM-view integration beyond command-palette mirrors.
- Any git-stash behavior changes (stash and shelf stay parallel, independent features, as in PyCharm).
- Locking out third-party git processes (impossible); their interference is detected, never overwritten by rollback, and recoverable.
