# Plan: GitHub Copilot commit-message generation in IntelliGit commit panel

_Locked via grill — by Claude + Mahesh. Revised after Codex Rounds 1–6._

## Goal

Add native-VS-Code-style AI commit-message generation to IntelliGit's commit panel: a per-repository sparkle button that generates a commit message from the currently checked files' diff, using the user's GitHub Copilot subscription through VS Code's official Language Model API (`vscode.lm`), streaming into the existing per-repo commit-message textarea. Behavior matches native git/Copilot generation — including honoring the user's `github.copilot.chat.commitMessageGeneration.instructions` setting — while respecting IntelliGit's checkbox-based commit model (commit operates on `checkedPaths`, not the git index).

## Approach

1. **Generator module** — new `src/ai/commitMessageGenerator.ts`:
   - `vscode.lm.selectChatModels({ vendor: "copilot" })`; pick first model from a small family-preference list, fallback to first returned. Empty list → typed `CopilotUnavailableError`.
   - Pure prompt-builder function (unit-testable) composing: (a) unified diff of checked paths, (b) last ~10 commit subjects (`git log --format=%s -n 10`) as style context, (c) commit instructions per the documented `github.copilot.chat.commitMessageGeneration.instructions` schema — an array of `{ "text": string }` and `{ "file": string }` entries (`{file}` resolved against the target repository's workspace folder, read with a bounded size cap; unreadable/malformed entries skipped with a log line, never fatal), (d) output instruction: subject line + optional body, no markdown fences.
   - **Token-aware budget**: select the model first, then fit the prompt to `model.maxInputTokens` minus an output margin using `model.countTokens` (bounded trim: coarse char pre-cap ≈40k → count → proportional trim → recount, max 2 iterations). Truncation stated inside the prompt.
   - `model.sendRequest(..., CancellationToken)`; async chunk stream; map `vscode.LanguageModelError` codes (`NotFound` / `NoPermissions` / `Blocked` / other) plus cancellation to typed results.
   - **Empty output is a failure, not a success**: a stream that ends with only empty/whitespace text yields a typed `EmptyResultError` — never a `done`.
2. **Diff assembly** — extend `src/git/operations.ts` (`GitOps`): `getDiffForPaths(root, paths, { includeHead })`:
   - **Acquisition-time limits, never buffer unbounded**: `git diff --numstat` pre-pass; **per-file caps AND a cumulative byte budget across all sources** (tracked diffs, untracked add-diffs, amend `git show` patch, instruction files) enforced while acquiring — files beyond either cap are represented as one-line change summaries; bounded reads for untracked file content.
   - Tracked checked files: `git diff HEAD -- <paths>`; untracked checked files rendered as add-diffs (reuse existing patch-helper patterns, e.g. `services/gitHelpers.ts`).
   - **Rename pairs are expanded host-side, from one snapshot**: the webview only ever sends rename **destinations** (its selectable set contains only `file.path`); after destination validation (Approach 3) the host builds a destination→source rename map from the **same fresh porcelain status snapshot** used for validation (the parser already captures `sourcePath` — workingTree.ts keeps it at parse level; surface it) and expands pairs internally, so diff, staging, and commit all see both halves of the rename while sources are never accepted from the webview payload nor rejected against the destination-only selectable set.
   - **All pathspec-taking invocations (numstat, diff, commit, show) go through the existing `withLiteralPathspecs` mechanism** (git/operations.ts already uses it for add/reset/checkout/stash) so wildcard/magic characters in filenames cannot expand beyond `checkedPaths`.
   - **Unborn HEAD** (no commits yet): diff against the repository's empty-tree ID **derived at runtime** (`git hash-object -t tree` on empty input — correct for both SHA-1 and SHA-256 object formats; never the hard-coded SHA-1 constant); commit-subject context becomes empty; generation still works for the first commit.
   - `isAmend`: additionally include `git show --format= HEAD` patch (skipped on unborn HEAD), counted against the cumulative budget. Amend with zero checked paths = HEAD patch only — **rejected on unborn HEAD, where no diff source exists** (see Approach 3).
3. **Host wiring** — `src/views/CommitPanelViewProvider.ts` **and** `src/views/UndockedViewProvider.ts` (both host the commit tab; wired identically) **plus one shared root-keyed generation coordinator**:
   - **Cross-host generation coordinator** (new small module `src/ai/commitMessageGenerationCoordinator.ts`, created once in activation, injected into **both** providers): the docked sidebar and the undocked panel coexist with independently selected roots (repositoryMode.ts `ensureUndockedPanel`) and share the same `commitDraft:<root>` workspaceState namespace (CommitPanelViewProvider.ts:97, UndockedViewProvider.ts:250), so "one active generation per root" must hold **across hosts, not per provider**. The coordinator holds the per-root active generation (requestId, owning host, CancellationTokenSource, root-bound `gitOps`); a new request for the same root from **either** host supersedes: the prior token is cancelled, its host receives a correlated `cancelled` terminal **marked `superseded: true`**, and all further emissions from the stale `requestId` are suppressed.
   - **Winner-only persistence, enforced mechanically**: a `superseded` terminal restores the losing webview's snapshot **locally only — it does not post `saveCommitDraft`** (the existing save message is uncorrelated, and a hidden webview can deliver its restore arbitrarily late, so a losing save could otherwise land after and overwrite the winner's). Only non-superseded terminals (the winner's `done`/`error`, or a user-initiated `cancelled`) persist. Manual typing in the peer host keeps today's last-writer-wins semantics on the shared key — pre-existing behavior, unchanged by generation.
   - **Commit fencing — commits and generation never interleave**: every commit action for a root (`commitSelectedFromPanel` in **both** providers, normal and amend) runs under a **root-scoped commit lease** acquired from the coordinator and released in `try/finally` around the complete action. Acquiring the lease **cancels the root's active generation and delivers its owner a correlated non-persisting cancellation** — `cancelled` with `superseded: true`, so the owning webview restores and unlocks but never posts `saveCommitDraft` (full emission suppression would leave that webview locked forever, and an ordinary persisting `cancelled` could write its snapshot after the commit clears the shared draft); only chunks and any late `done`/duplicate terminals from the fenced request are suppressed. **While the lease is held, new generation requests for that root are rejected with a correlated error** — the fence spans the entire commit action, so no generation can start against mid-commit repository state. The webview additionally disables commit/amend controls while its own generation is `requested`/`running`; cross-host commits are covered by the host-side lease, not the webview.
   - Message protocol mirrors the existing commit flow (selection is webview-owned there too — `commitSelectedFromPanel` already receives `paths` from the webview): `generateCommitMessage { repositoryRoot, requestId, paths, amend }` and `cancelCommitMessageGeneration { repositoryRoot, requestId }`.
   - **Validation at the boundary** (repo standing rule): `repositoryRoot` resolved through the existing `runtimeForMessage`-style lookup (`assertString` + discovered-runtimes map; unknown root rejected); `paths` asserted as strings and **validated against a fresh host-derived selectable set built with the same rule as the webview's `buildSelectablePathSet` — ignored (`!`) entries excluded** — so an ignored file's contents can never be sent to Copilot; `amend` asserted boolean. The selectable set contains rename **destinations** only; sources are expanded host-side afterwards from the same snapshot (Approach 2). **Zero-path requests are rejected with a correlated error when `amend` is false (subset validation must not accept the empty set vacuously — there is nothing to describe) and when `amend` is true on an unborn HEAD (no HEAD patch exists)**. No host-owned selection mirror — the webview stays the single source of truth for selection, the host validates rather than duplicates it.
   - **Operation-state guard — armed watcher, checked twice, race-free terminals**: a single whole-index-operation predicate checks `MERGE_HEAD`, `CHERRY_PICK_HEAD`, **`REVERT_HEAD`** (revertCommit runs `git revert` and can leave sequencer conflict state — commitBasicActions.ts:215), and rebase state (`rebase-merge`/`rebase-apply`) via the runtime's `gitOps`. On accepting a request the coordinator **first arms a watcher** on that root's **resolved git dir** (worktree-aware, same `gitdir:` resolution as RefreshService.resolveGitDir) for those marker paths, **then runs the request-time predicate check** — arm-before-check, so a marker appearing between check and watch cannot be missed; a marker appearing mid-generation cancels the root's active generation. Because watcher delivery is asynchronous, **`done` is claimed atomically: the coordinator re-runs the predicate immediately before emitting `done` and converts to `cancelled` if a whole-index marker has appeared** — a generation can never complete into an active merge/sequencer state. The watcher exists only while a generation is active and is disposed at terminal. RefreshService is **not** relied on for any of this — it watches only the active docked root and its `gitStateFiles` set includes neither `CHERRY_PICK_HEAD` nor `REVERT_HEAD`, while the undocked host can be generating for an independently selected root.
   - **Cancellation is cooperative and effective at every pre-start boundary**: the coordinator creates the request's CancellationTokenSource at acceptance, but token creation alone aborts nothing — `vscode.lm.selectChatModels` takes no token and the git executor (`spawn` in executor.ts:90) has no kill plumbing. So: model selection is **raced against the token** (on cancel, the orphaned promise is discarded); every acquisition step checks the token at its await boundary and discards results after cancellation; the in-flight git subprocess is left to finish harmlessly (all pre-start git calls are read-only diff/show/status already bounded by the acquisition byte caps) — no subprocess-kill plumbing in v1. Cancel during `requested` (user stop, supersede, operation-state transition, host disposal) therefore yields a prompt correlated `cancelled` terminal without waiting for pre-start work. **Orphaned work is bounded by a per-root acquisition slot**: the diff-acquisition phase holds the root's slot until its spawned git work settles — even after its request was cancelled — and a successor generation's acquisition waits on that slot (the wait itself cancellable), so rapid stop/regenerate cycles can never stack more than one in-flight acquisition's processes per root; cancellation still returns its terminal immediately, only the successor's acquisition start is delayed.
   - **Every accepted request emits a correlated terminal**: boundary rejections, model-selection failures, and diff-acquisition failures that occur **before** any `start` still produce `error { repositoryRoot, requestId, errorKind }` — a request can never dead-end into a generic uncorrelated error path.
   - The generation request captures the **runtime's root-bound `gitOps` once at start**; active generations are **cancelled on repository switch and on provider disposal** (the coordinator drops a host's generations when that host disposes).
   - Host → webview events: `commitMessageGeneration { repositoryRoot, requestId, kind: "start" | "chunk" | "done" | "cancelled" | "error", text?, errorKind?, superseded? }`.
   - **Availability/quota/consent errors surface host-side via `vscode.window.showErrorMessage`/`showInformationMessage` with action items** — the existing `showTimed*` helpers are message-only and stay untouched. `NotFound` → items "Install Copilot" (opens extension page) / "Sign In"; each selected action is executed and tested. The webview only restores state.
4. **Webview state** — docked **and** undocked paths:
   - `src/webviews/react/commit-panel/hooks/useExtensionMessages.ts` reducer: per-repo `generation: { status: "idle" | "requested" | "running", requestId?: string, snapshot?: string }`.
   - **Request lifecycle**: the webview dispatches a local `generationRequested { requestId }` action **before** posting to the host — this action **takes the snapshot and locks the textarea immediately**, so a pre-start host failure (`error` with matching ID, no prior `start`) cleanly restores and unlocks; `start` (exact ID) clears the textarea and begins streaming; all inbound events require an exact `requestId` match (stale events ignored).
   - `chunk` → append; `done` (non-empty only — host guarantees) → idle, keep text; `cancelled`/`error` → restore snapshot. **Empty/whitespace-only outcome arrives as `error`, restoring and persisting the snapshot** — a user's draft can never be replaced by nothing.
   - **Textarea is read-only from `requested` through terminal**; the stop button is the only interaction and is **available in both `requested` and `running`** — pre-start waits (model selection, diff acquisition) are cancellable, not just the stream (host side: race-and-discard cancellation, Approach 3). Commit/amend controls are disabled while generation is `requested`/`running` (Approach 3 commit fencing).
   - On every **non-superseded** terminal event the webview posts the existing `saveCommitDraft` message with the resulting text, so the persisted per-repo draft (`commitDraft:` workspaceState) always matches the screen; a `superseded: true` terminal restores the snapshot **without posting** `saveCommitDraft` (winner-only persistence, Approach 3).
   - **Undocked wiring enumerated, not implied** (real module paths): equivalent reducer/handler/action changes in `src/webviews/react/undocked/commitPanelState.ts`, `src/webviews/react/undocked/useUnifiedMessages.ts`, and `src/webviews/react/undocked/useUndockedActions.ts` (generation events, cancellation, draft persistence), with their own tests.
5. **UI** — `src/webviews/react/commit-panel/components/CommitArea.tsx`: sparkle icon button overlaid top-right of the textarea (24px icon-button system, theme tokens); it becomes a stop button (cancel) **from `requested` through terminal**; disabled when nothing is checked and amend is off, when amend is on with zero checked paths on an unborn HEAD, **and while a whole-index operation is in progress**; commit/amend controls disabled while generation is active. The operation signal is **host-derived and transported explicitly**: both providers add a `wholeIndexOperationInProgress: boolean` field (computed by the shared predicate of Approach 3) to their commit-panel update payloads; both reducers store it; `CommitTab`/`CommitArea` consume it for sparkle eligibility. The existing webview-derived `hasMergeConflicts` (`files.some(status === "U")` — CommitTabController.ts:145) **cannot** see clean merges/cherry-picks/reverts/rebases and stays untouched for its abort-merge purpose; the host-side request-time guard remains authoritative either way. New i18n keys through the l10n pipeline (all locale files).
6. **Commit-accuracy prerequisite (pre-existing bug fix)** — `src/views/commitPanelActions.ts` `commitSelectedFromPanel` currently stages checked paths then runs a bare `gitOps.commit()`, so files staged earlier but **unchecked** in the panel silently ride into the commit. Fix with explicit branches, all pathspecs via `withLiteralPathspecs`, **rename pairs expanded to source+destination** (see Approach 2):
   - Normal commit with paths: pathspec-scoped commit (`--only -- <paths>` semantics) so the commit's **changed set** is exactly `checkedPaths` (with rename sources included, a checked rename commits both the deletion and the addition).
   - **Zero-path amend: `--amend --only` with no paths** — amends the message without sweeping in staged content.
   - **Whole-index operation in progress** (`MERGE_HEAD`/`CHERRY_PICK_HEAD`/`REVERT_HEAD`/rebase state — same shared predicate as Approach 3): git refuses partial commits — keep today's bare whole-index commit semantics for merge/sequencer completion, unchanged.
   - Regression tests: previously-staged-unchecked file excluded; deleted / renamed / wildcard-and-literal-special-char paths; amend with and without checked paths; merge-in-progress **and revert-conflict** commits still complete.
   - **Real-repository assertion, stated precisely and recursively**: a commit's tree always retains unchanged tracked files, so "exactly the checked paths" is asserted on the **root-aware changed-path set** with plumbing flags pinned: `git diff-tree --root -r --no-commit-id --no-renames --name-status <commit>` must equal the expected checked set (`--root` compares a root commit against its empty tree and otherwise compares against its parent; `-r` because bare diff-tree collapses nested changes to directory entries; `--no-renames` so a checked rename deterministically appears as source-delete + destination-add), and **recursive** `git ls-tree -r` additionally verifies the rename source absent, the destination present, and an untouched tracked file still retained — including nested paths.
7. **Tests** — deterministic matrix:
   - Diff assembly: tracked / untracked / deleted / renamed (destination validated, source expanded from the same snapshot) / wildcard-magic filenames (literal pathspecs) / unborn HEAD (SHA-1 **and** SHA-256 where the CI git supports `--object-format=sha256`, capability-guarded) / amend / amend-with-zero-checked; per-file and cumulative budget truncation.
   - Generator: prompt builder (truncation summary, instructions schema variants incl. unreadable and oversized `{file}`, subjects context, amend), token-budget trim bounds, **empty-output → `EmptyResultError`**.
   - Reducer (docked + undocked): `generationRequested` snapshots + locks before `start` (initial start accepted, stale start rejected, **pre-start error restores and unlocks**), chunk append, stale-`requestId` ignored, cancelled vs error terminals, **empty-result restore**, **`superseded` terminal restores without posting `saveCommitDraft`**, draft-persistence posts on each non-superseded terminal, commit/amend controls disabled while active, independent concurrent repos.
   - Coordinator/host: supersede cancels prior + suppresses stale emissions **including cross-host on the same root** (docked superseded by undocked and vice versa; **persistence-race test: the losing terminal never persists — only the winning generation's terminal drives the final draft write, even when the losing webview delivers late**); **commit fencing: commit during active generation (same host and cross-host) acquires the lease; the fence terminal restores + unlocks the owner without persisting, even when delivered after the commit cleared the shared draft; a generation request during a held lease is rejected with a correlated error; no stale terminal can write the draft after the commit**; **cancel during `requested` — before `start` — aborts promptly via race-and-discard with a `cancelled` terminal**; **acquisition-slot bound: rapid cancel/regenerate cycles never exceed one in-flight acquisition per root, and the successor's slot wait is itself cancellable**; repository-switch and provider-disposal cancellation; unknown-root rejection; **ignored-path (`!`) rejection**; **zero-path normal rejection**; **unborn zero-path-amend rejection**; **rename destination accepted, never-selectable path rejected**; **operation-state: arm-before-check (a marker injected after arming and before the predicate check is still caught), request-time rejection, mid-generation transition cancellation, and the done-claim re-check (marker appearing just before completion converts `done` → `cancelled`) for merge, cherry-pick, revert, and rebase — exercised on the active docked root, a non-active root, and an independently selected undocked root**; every pre-start failure emits a correlated `error`; notification action items execute their commands.
   - Eligibility: disabled states incl. `wholeIndexOperationInProgress` (a **clean** merge — no conflict rows — still disables) and unborn zero-path amend.
8. **Gates** — full repository-required validation before acceptance: typecheck, lint, unit tests (`.claudex-gates.json`), `build`, `architecture:check`, `react-doctor`, `l10n:validate` + `l10n:audit` (and the l10n sync/translate/import pipeline for the new keys), `npx --yes impeccable detect` for affected UI paths, then manual rendered verification of the sparkle flow in **both docked and undocked** hosts.

## Key decisions & tradeoffs

1. **`vscode.lm` direct — NOT the native `github.copilot.git.generateCommitMessage` command.** The native command is an undocumented internal ID, generates from staged/all changes (ignores IntelliGit checkboxes), writes into the native SCM input box as a side effect, and cannot stream into our panel. Rejected after explicit cost comparison during the grill; permanently out of scope unless users report style mismatch.
2. **No `AIProvider` abstraction.** Deliberate deviation from `docs/gitlens/gitlens_features_implementation_plan.md` M6, which sketches an interface for future BYOK. One implementation exists today; the interface gets extracted when a second provider actually lands. BYOK remains future work.
3. **Checked-paths diff, not staged diff — and the commit itself is made to honor that contract.** The message must describe what the Commit button actually commits; Approach 6 fixes the staged-but-unchecked leak (and the rename-pair gap) so `checkedPaths` is the single source of truth for both. Whole-index operations (merge and sequencer states, including revert) are the documented exception (whole-index commit, generation disabled and host-guarded).
4. **Overwrite + snapshot/restore, request-scoped.** Generation replaces the current message (native parity). The pre-generation message is snapshotted at `generationRequested`; cancel (available from `requested` onward), error (including pre-start failures), or empty output restores it; the textarea is read-only from request to terminal so typed text can never race the stream.
5. **Honor `github.copilot.chat.commitMessageGeneration.instructions` (full documented schema); zero new IntelliGit settings.** Existing native tuning transfers unchanged, including `{file}` instruction entries. No model picker, no custom prompt key in v1.
6. **No secret-redaction pass in v1 — but ignored files are excluded by validation.** Deviation from the M6 doc's redaction note: the diff goes to the user's own Copilot subscription, the same trust boundary as native VS Code. The host-side selectable-set validation (Approach 3) independently guarantees ignored (`!`) files — the classic secrets location — can never enter a prompt.
7. **Always-visible sparkle.** Copilot unavailable → actionable host-side notification on click (Install / Sign In). No reactive hide, no `onDidChangeChatModels` subscription in v1.
8. **Validated webview boundary, request-correlated events.** Follows the repo's standing "never trust webview `repositoryRoot`" rule; `paths`/`amend` travel with the request exactly as the existing commit flow does and are validated against a fresh host-derived selectable set — **no host-owned selection mirror** (a second source of truth that can desync was reviewed and rejected in favor of validation).
9. **One generation coordinator across both hosts; winner-only persistence via superseded-skip, not an epoch protocol.** Docked and undocked providers are separate instances over the same repositories and the same `commitDraft:` namespace; per-provider "one active generation" would still allow a cross-host draft race. The coordinator is deliberately small — per-root active-generation map, supersede, a commit lease spanning each commit action, a per-root acquisition slot, and a request-scoped operation-state watcher — and owns lifecycle only; validation stays at each provider's message boundary. For persistence, the reviewed epoch-correlated-save alternative was **rejected as over-scoped**: tagging losing terminals `superseded` and skipping their `saveCommitDraft` post achieves winner-only persistence without changing the existing uncorrelated save protocol or locking peer editing; manual peer-host typing keeps its pre-existing last-writer-wins semantics.
10. **Cooperative cancellation, no subprocess kill in v1.** `selectChatModels` and the git executor accept no cancellation; Stop is implemented as race-and-discard at every pre-start await boundary. The orphaned work is read-only, byte-capped, and bounded to one in-flight acquisition per root by the acquisition slot, so letting it finish silently is harmless; kill plumbing for the executor was **rejected as unneeded scope** for read-only diff acquisition.

## Risks / open questions

- Approach 6 changes core commit behavior (pathspec-scoped commit) — the regression matrix is the containment; behavior change is user-visible only in the buggy cases (staged-but-unchecked leak, rename-source drop) and explicitly not applied during whole-index operations.
- Model availability varies by Copilot plan; org policy can deny LM API access (`NoPermissions` at consent) — surfaced via host notification, nothing else to do.
- `countTokens` cost on large prompts is bounded by the 2-iteration trim; margin constant may need tuning against real models.
- Streaming into a controlled React textarea re-renders per chunk; coalesce only if profiling shows jank (unlikely at commit-message size).
- First `sendRequest` triggers VS Code's one-time consent dialog — host-side, nothing to build, but the first use has a pause.
- SHA-256-repo tests depend on the CI git build supporting `--object-format=sha256`; capability-guarded so unsupported environments skip, not fail.
- The coordinator introduces shared state between hosts; contained by making it the sole owner of generation lifecycle (providers never track "active generation" themselves) and by request-scoped watchers (created at accept, disposed at terminal — no standing watchers).
- Cooperative cancellation leaves an orphaned read-only git subprocess running to completion after Stop; bounded by the acquisition byte caps and the per-root acquisition slot (at most one in-flight acquisition per root), so no correctness or resource-pileup impact — revisit only if profiling shows waste.
- Undocked wiring spans three additional webview modules under `src/webviews/react/undocked/` — enumerated in Approach 4; divergence discovered at build time gets reported, not silently absorbed.

## Out of scope

- Stash/shelf description generation, commit explanations, changelog, Commit Composer (M6 siblings).
- BYOK providers (Anthropic/OpenAI keys), model picker, any new settings.
- Command-palette command; secret redaction; reactive button hiding.
- Native `github.copilot.git.generateCommitMessage` bridge.
